How work is verified

Rinux is run as an evidence-driven project: a claim is only as strong as a reproducible gate on a clean commit.

Defect state machine

OBSERVEDreproducible symptom
ROOT_CAUSE_CANDIDATEhypothesis, no proof
FIX_CANDIDATEcode + regression test
QUALIFIEDgate passed on fresh clean build
CLOSEDindependent review accepted

The author of a change may report at most FIX_CANDIDATE. A failed invariant afterwards moves a qualified item to REGRESSED.

Test ladder

focused testwhile iterating
subsystem test
just checkonce before handoff
QEMU gatehardware / entry / scheduler / MMU / storage / GUI
stress / soakconcurrency & release only
just check        # lint, ABI and policy checks, unit tests
just test-smoke
just --list       # all recipes

Evidence

Formal evidence records the exact commit and clean-tree status, build profile and toolchain, fresh artifact SHA-256, commands with exit codes and every failed attempt, and observed invariant values. Retries may diagnose infrastructure but never turn a failing product scenario into a pass.
